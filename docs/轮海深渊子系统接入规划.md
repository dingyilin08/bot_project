# 轮海深渊子系统接入规划

## 一、规划目标

在现有异步 Python QQ 机器人 RPG 中接入“轮海深渊”无尽挑战玩法，复用当前六世界副本怪物、持久化回合战斗、角色战斗快照、灵兽/赛季/宗门增益和幂等奖励账本，并补齐深渊独立进度、定级赛、排行榜、菜单与文本交互。

本规划只定义接入方案，不在本阶段直接实现玩法代码或执行生产数据库迁移。

## 二、现有实现审阅结论

本次仅审阅当前玩法代码与数据库快照，没有查阅 `docs` 文件夹中的旧文档。

| 现有能力 | 当前实现 | 深渊接入方式 |
| --- | --- | --- |
| 六世界副本及怪物池 | `Game_main/g6_dungeon.py`、`data_dungeon`、`data_monster` | 按深渊层段复用六世界对应档位的副本和怪物模板 |
| 怪物基础属性 | `DUNGEON_BASE_STATS`、`_interpolate_base_stats()`、怪物属性倍率 | 抽成可复用规则，深渊以第一档基础属性乘层数与跨界倍率 |
| 持久化回合战斗 | `Game_domain/battle_*`、`Game_main/g11_battle.py` | 每只深渊怪物创建 `ABYSS` 类型 Battle Session，重启后可恢复 |
| 单人 PVE 快照 | 副本开战时冻结洞府、宗门、赛季、灵兽、专属等效果 | 深渊开启时冻结整场角色与长期增益，后续30只怪物均复用同一快照 |
| 奖励幂等 | `Game_domain/reward_service.py`、`reward_ledger` | 扩展仙玉奖励并允许深渊结算与进度更新共用同一事务 |
| 战力排行榜 | `Game_main/g8_power.py` | 复用 Markdown 排版与分页方式，排名数据由深渊进度实时派生 |
| 指令与菜单 | `output_main.py`、`Game_main/g0_menu.py` | 注册深渊指令，加入活动菜单与副本菜单，所有关键操作提供文本交互 |

必须先处理的现有耦合：`Game_main/g11_battle.py` 当前将所有完成的 Battle Session 都交给普通副本结算。接入深渊时应按 `battle_type` 分发至不同结算器，避免深渊战斗被误判为普通副本。角色“出战/收回”入口目前也未统一检查活动中的 Battle Session，需增加战斗占用校验，才能真正做到深渊开战后禁止换角。

## 三、规则消歧与落地口径

原设计存在几处边界冲突。为保证规则可实现、可测试且不会形成无限刷奖漏洞，本规划采用以下口径。

### 3.1 层数、波次与星级

- 玩家初始最高通关层为0，首次可挑战第1层。
- 每层固定6波，每波5只，共30只；一波5只全部击败后自动生成下一波。
- 累计击杀达到10只即满足本层通关条件，并解锁结算选择；达到20只提升为2星；达到30只提升为3星并自动结算。
- 原稿使用“＞10、＞20、＞30”，会导致击杀10只没有星级、最多30只却永远无法3星。本规划修正为“≥10、≥20、≥30”。
- 达到10或20只后，玩家可以立即结算当前星级，也可以继续冲击更高星级。
- 未满10只战败或主动退出，判定本层失败，不发奖励、不解锁下一层。
- 已满10只后继续挑战并战败，按战败前已达到的星级结算，避免“已经通关却因冲星失去全部收益”。

### 3.2 进度与重复挑战

- 普通深渊默认挑战“最高已通关层 + 1”；已通关层允许从记录页重打以补星，但不能重复领取已经获得的星级奖励。
- 每层经验只在首次通关时发放一次；灵石与仙玉按该层历史最高星级发放，升星只补发新旧星级奖励差额。
- 该规则与“定级赛不可重复获得既有层数奖励”的原意一致，并防止无次数限制的深渊被用于无限获取仙玉。
- 排行进度以最高通关层为准，不以当前正在挑战的层数为准。

### 3.3 定级赛

- 任一角色达到50级后，账号解锁定级赛入口；实际参赛角色也必须达到50级。
- 定级目标层采用明确的1:1公式：`目标层 = 参赛角色当前等级`。因此100级对应100层。
- 原稿中的“100级直接挑战200层”与1:1公式及前文示例冲突，本规划不采用200层示例。
- 玩家最高通关层大于或等于目标层时，不允许开启定级赛。
- 定级赛成功后，仅为尚未领取的1至目标层奖励发奖；已有普通深渊进度或历史星级的层数只补差额，绝不重复发放。
- 定级赛目标层的实战星级作为本次批量层级的结算星级。例如100层定级获得2星，则1至100层均按2星计算，但已有更高星级记录不回退。
- 定级赛失败不修改永久进度、不发奖，允许无次数限制重试。

### 3.4 怪物池映射

现有数据库中六个世界各有10档副本，最低等级依次为1、10、20……90。深渊按层段映射到同档怪物池：

| 深渊层数 | 六世界候选副本档位 |
| --- | --- |
| 1～10层 | 各世界第1档副本 |
| 11～20层 | 各世界第2档副本 |
| 21～30层 | 各世界第3档副本 |
| …… | …… |
| 81～90层 | 各世界第9档副本 |
| 91层及以上 | 各世界第10档副本，属性继续随深渊层数无限成长 |

首次进入某层预览时，从六个世界中随机确定一个世界，再锁定该世界当前档位的副本怪物池。预览记录保存世界、副本和随机种子；正式开战时才冻结当前出战角色并生成第一波。后续每波的实际怪物实例在生成时落库，重复查看页面或服务重启不得重新抽取。

每波从该怪物池抽取5个模板，允许同名怪物重复。默认按“4只普通怪 + 1只Boss”生成，以免现有每档2普通、1Boss的数据结构导致Boss比例失控；Boss固定放在每波第5位。若产品希望完全等概率抽取，可在开发前调整为配置项。

预览页显示：目标层、抽中的世界、来源副本、该世界同界角色、当前出战角色是否跨界、怪物属性倍率、预估奖励与角色冻结提示。

### 3.5 怪物属性

核心公式保持原设计：

```text
层数倍率 = 1 + 0.05 × 深渊层数
跨界倍率 = 当前角色世界与本层世界不同时取1.20，否则取1.00
最终属性 = 第一档副本基础属性 × 怪物模板属性倍率 × 层数倍率 × 跨界倍率
```

- 第1层按原公式即为基础值的105%，不擅自改成 `层数 - 1`。
- 气血、攻击、防御、速度、暴击、暴伤、闪避、命中均按该公式计算并向下取整；战斗引擎已有的命中、暴击等上限仍然生效。
- 怪物技能与Boss机制复用来源模板；来源世界与当前角色世界不同时，在预览和战斗页明确标记“跨界压制：怪物全属性+20%”。
- 深渊整场使用开战时保存的角色、装备、技能、灵兽和各类PVE增益快照，玩家中途提升养成不会改变已开始的挑战。
- 角色血量默认沿用当前单人副本体验：下一只怪继承战后血量比例并恢复30%最大气血。该项原设计未明确，应做成 `ABYSS_POST_BATTLE_HEAL_BP=3000` 的可调规则。

### 3.6 奖励计算

单层满额奖励公式：

```text
经验 = floor(参赛角色当前等级升级所需经验 ÷ 1016)
灵石 = floor(300 × (1 + 0.05 × 层数 × 星级))
仙玉 = 星级 × 30
```

- “升级所需经验”在整场开启时冻结，避免战斗中升级导致同一层奖励漂移；100级当前已是等级上限，所需经验为0，因此经验奖励为0。
- 经验与星级无关，每层只领取一次。灵石和仙玉升星时只领取差额。
- 定级赛批量结算时逐层应用上述公式，再汇总展示；每一层均写独立业务键，任意重试都不会重复发奖。
- 奖励不包含普通副本的技能卷轴、装备、本源材料或专属掉落，除非后续设计另行增加。
- 以100层3星定级为例，仅仙玉理论总量即为9000。实现阶段应把定级成功率、仙玉产出和祈愿消耗纳入上线观测，但不得在代码中暗改设计公式。

## 四、玩家指令与交互

### 4.1 指令清单

| 指令 | 参数 | 功能 |
| --- | --- | --- |
| `深渊` / `深渊菜单` | 无 | 查看进度、当前角色、可挑战层、定级资格和快捷入口 |
| `深渊预览` | `层数`可选 | 创建或复用下一层预览，查看世界、克制、倍率和奖励 |
| `挑战深渊` | `层数`可选 | 开启普通深渊挑战；省略时挑战最高通关层+1 |
| `深渊怪物` | 无 | 查看当前波、5只怪物及击杀/星级进度 |
| `挑战深渊怪物` | `编号` | 对当前波指定怪物发起回合战斗 |
| `深渊结算` | 无 | 达到10或20击杀后按当前星级主动结算 |
| `离开深渊` | 无 | 未达通关线时放弃本次挑战 |
| `深渊定级` | 无或`开始` | 查看资格与收益预览，二次确认后开始定级赛 |
| `深渊排行` | `页码`可选 | 查看全服最高层排行榜及自身名次 |
| `战斗状态` / `战斗行动` | 沿用现有参数 | 继续当前深渊怪物的持久化回合战斗 |

### 4.2 文本交互原则

- `深渊` 首页直接提供“预览下一层、开始挑战、定级赛、排行榜、返回活动菜单”按钮。
- 预览页的“开始挑战”按钮必须带完整层数，例如 `<qqbot-cmd-input text='挑战深渊 21' show='挑战第21层' />`。
- 每波怪物逐项提供可点击的“挑战1～5”按钮；已击败目标不再显示可挑战按钮。
- 10击杀后同时显示“按1星结算”和“继续冲星”；20击杀后显示“按2星结算”和“冲击3星”。
- 定级赛使用两步操作：首次 `深渊定级` 仅展示目标层、总奖励预估和失败无收益提示；玩家点击 `深渊定级 开始` 才创建挑战。
- 所有错误页都应给出下一步按钮，例如无出战角色时提供“角色背包”，已有战斗时提供“战斗状态”，未达50级时提供“当前角色”。

## 五、状态机与战斗流程

```text
无挑战
  → 预览并创建 READY 记录（只锁定世界、副本与随机种子，仍可换角）
  → 正式开战（冻结角色、PVE效果与奖励基准，生成第一波）
  → 选择怪物，创建 ABYSS Battle Session
  → 回合行动 WAITING_ACTIONS / RESOLVING
  → 单怪胜利：记录击杀、继承血量、推进波次
      ├─ 击杀不足10：继续挑战
      ├─ 击杀达到10/20：QUALIFIED，可结算或继续冲星
      └─ 击杀达到30：自动进入 SETTLING
  → 单怪失败
      ├─ 击杀不足10：FAILED，无奖励
      └─ 已达到通关线：按当前星级进入 SETTLING
  → 原子结算奖励和永久进度
  → SETTLED
```

定级赛与普通模式共用上述状态机，仅创建时的 `run_type`、目标层和成功后的批量层级结算范围不同。

## 六、数据库接入方案

新增迁移文件建议为 `数据库源文件/p6_abyss.sql`，所有表使用 InnoDB、utf8mb4，并带明确唯一键和查询索引。

### 6.1 `user_abyss_profile`

账号级永久进度，一名玩家一行。

- `uid`：主键。
- `highest_cleared_layer`：最高通关层，默认0。
- `total_kills`：历史累计击杀，用于展示与同层次级排序。
- `placement_unlocked`：可由等级实时判断，此字段仅在需要审计首次解锁时间时保留。
- `created_at`、`updated_at`。

### 6.2 `user_abyss_layer_record`

每层最佳成绩与奖励水位。

- 复合唯一键：`(uid, layer_no)`。
- `best_stars`、`best_kills`、`clear_count`。
- `exp_rewarded`：是否已发该层首次通关经验。
- `rewarded_stars`：灵石、仙玉已发到的最高星级。
- `first_cleared_at`、`updated_at`。

### 6.3 `abyss_run`

一次普通挑战或定级赛的可恢复主记录。

- `run_uuid`：主键，UUID字符串。
- `uid`、`run_type`（`NORMAL`/`PLACEMENT`）、`layer_no`、`role_id`；`role_id`在预览态可为空，正式开战时写入。
- `source_world`、`source_dungeon_id`、`rng_seed`。
- `state`、`wave_no`、`kill_count`、`player_hp_ratio`、`version`。
- `role_snapshot_json`、`effect_snapshot_json`、`reward_snapshot_json`。
- `created_at`、`settled_at`、`updated_at`。
- 使用“活动状态时等于uid、终态时为NULL”的生成列加唯一索引，保证每个玩家最多一个活动深渊挑战；同时创建挑战前锁定 `user_zt` 玩家行防并发。`READY`预览态不阻止换角，只有正式开战后才启用角色冻结校验。

### 6.4 `abyss_run_monster`

保存每一波已经生成的怪物实例。

- 唯一键：`(run_uuid, wave_no, slot_no)`。
- `source_monster_id`、`monster_name`、`monster_type`、`monster_snapshot_json`。
- `state`（`READY`/`FIGHTING`/`DEFEATED`/`SURVIVED`）、`battle_uuid`。
- `created_at`、`defeated_at`。

只需预生成当前波；波次完成后使用 `rng_seed + wave_no` 可重复地生成下一波并落库。这样既满足“一次生成5只”，也避免每个挑战预写30行。

### 6.5 奖励账本

不另建重复的货币账本，扩展现有 `reward_ledger` 与 `MySQLRewardService` 支持仙玉及外部事务。业务键建议为：

```text
abyss:{uid}:{layer}:exp
abyss:{uid}:{layer}:lingshi:star:{star}
abyss:{uid}:{layer}:xianyu:star:{star}
```

实际升星补差额时，可以每个星级分别记录增量，或将业务键写为目标星级并在同一行锁下比较 `rewarded_stars`。无论采用哪种方式，奖励账本、角色经验、玩家货币、层记录和最高层进度必须在同一数据库事务中提交或回滚。

## 八、关键服务接口建议

```python
def abyss_tier_index(layer_no: int) -> int: ...
def abyss_rating(kill_count: int) -> int: ...
def abyss_monster_multiplier(layer_no: int, cross_world: bool) -> float: ...
def calculate_abyss_layer_reward(required_exp: int, layer_no: int, stars: int) -> dict: ...
def calculate_reward_delta(previous_stars: int, new_stars: int, ...) -> dict: ...
def placement_target(role_level: int) -> int: ...

async def create_run(uid: int, layer_no: int, run_type: str) -> AbyssRun: ...
async def start_monster_battle(uid: int, slot_no: int) -> BattleSession: ...
async def settle_monster_battle(uid: int, battle_session: BattleSession) -> dict: ...
async def settle_run(uid: int, run_uuid: str) -> AbyssSettlement: ...
async def get_leaderboard(uid: int, page: int) -> dict: ...
```

所有SQL使用 `%s` 参数化；所有写操作使用明确事务；涉及Run、怪物状态、层记录或奖励时使用 `SELECT ... FOR UPDATE`，并通过 `version` 或唯一键处理重复点击。

## 九、排行榜规则

排行榜每页10人，排序建议如下：

1. `highest_cleared_layer` 降序；
2. 最高层 `best_stars` 降序；
3. 历史 `total_kills` 降序；
4. 该最高层首次通关时间升序；
5. `uid` 升序，保证完全同分时结果稳定。

页面展示名次、玩家名、最高层、最高层星级、累计击杀，并单独显示当前玩家名次。排行榜只读永久成绩，不读取活动Run，避免未结算数据提前上榜。

## 十、异常、并发与恢复

- 同一玩家不能同时进行普通副本怪物战、深渊怪物战或另一场单人 Battle Session；发现活动会话时引导至 `战斗状态`。仅有 `READY` 深渊预览时仍可换角，正式开战后才禁止 `出战` 与 `收回`。
- QQ 重复投递使用请求ID、Battle Action UUID和奖励业务键三层幂等保护。
- 服务重启后，`abyss_run`、怪物快照和 `battle_session` 足以恢复；不得重新抽世界、重新生成怪物或重新计算冻结增益。
- Battle Session 已结束但深渊未结算时，玩家再次发送 `战斗状态` 或 `深渊` 应触发幂等补结算。
- 奖励写入成功但响应发送失败时，重复请求只能重放结算结果，不能再次加货币。
- 结算失败时Run保留为 `SETTLING`，不得先将其标为已完成；后台或玩家下次查询可以继续补偿。
- 角色被管理员删除、模板怪物被修改等异常不影响进行中的Run，因为关键角色和怪物数据已经冻结在JSON快照中。

## 十一、测试与验收

### 11.1 规则测试

- 层数1、10、11、90、91、100及超高层的怪物池档位正确。
- 第1层倍率1.05；同界无额外倍率；跨界再乘1.20；各属性统一向下取整。
- 击杀9/10/19/20/29/30分别得到0/1/1/2/2/3星。
- 灵石、仙玉和经验公式在1、2、3星下正确；升星只返回差额。
- 49级不能定级，50级目标50层，100级目标100层；已有进度不允许重复定级。

### 11.2 服务与事务测试

- 创建Run时固定角色、世界、随机种子和PVE效果；切换页面不改变结果。
- 每波恰好5只且默认4普通1Boss；击败5只后只生成一次下一波。
- 重复点击同一怪物、重复提交同回合行动、重复结算均不重复增加击杀或奖励。
- 10击杀结算解锁下一层；20击杀补2星差额；30击杀自动3星。
- 10击杀后战败按1星结算，9击杀后战败不发奖。
- 定级失败永久进度不变；定级成功只结算未领奖层与升星差额。
- 奖励、层记录和最高层任一写入失败时整个事务回滚。
- 深渊进行中执行 `出战` 或 `收回` 被拒绝；结算完成后恢复正常。
- 普通副本结算回归测试通过，`SOLO_DUNGEON` 与 `ABYSS` 不串结算器。

### 11.3 指令与界面测试

- 所有新指令同时出现在解析器命令列表和 `content()` 路由中。
- `深渊`、活动菜单、副本菜单均能进入玩法；所有按钮的 `text` 是机器人可识别的完整指令。
