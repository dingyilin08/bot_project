# 世界消息子系统设计与实施规划

## 1. 目标与边界

世界消息用于在玩家触发机器人回复时附带简短攻略提示，不主动向全部群聊广播。普通回复尾注按“官方群提示 → 世界消息 → 官方群提示”的顺序全局交替；每次进入世界消息槽位时，再从已启用消息中按 ID 循环选择下一条。

机器人入群和玩家添加机器人后的欢迎消息继续固定展示官方群群号，避免新玩家错过官方群入口。

## 2. 子系统划分

- `Game_domain/world_message_service.py`：消息库读写、GM 权限校验、参数校验、软删除和数据库轮换游标。
- `Tool/qq_reply_footer.py`：为纯文本、Markdown 和 Keyboard 回复幂等追加轮换尾注。
- `Game_main/g27_world_message.py`：GM 菜单以及添加、修改、启用、停用、删除指令。
- `数据库源文件/p2_world_message.sql`：消息表、轮换状态表和首批攻略消息。
- `main.py` / `bot_main.py`：Webhook 与 WebSocket 的普通回复出口统一接入轮换尾注。

## 3. 数据模型

`world_message` 保存正文、内容哈希、启用状态、软删除状态和创建/更新管理员。内容哈希唯一，平台重投“添加”指令时不会生成重复消息；软删除使重复删除保持幂等。

`world_message_state` 保存全局下一槽位和上一条世界消息 ID。选取时使用 `SELECT ... FOR UPDATE`，保证多个 Webhook/WebSocket 实例并发回复时仍能正确交替。

## 4. GM 指令

- `GM世界消息`：查看消息库与状态。
- `GM世界消息添加 内容`：添加并启用攻略消息。
- `GM世界消息修改 ID-新内容`：修改正文。
- `GM世界消息启用 ID` / `GM世界消息停用 ID`：控制是否参与轮播。
- `GM世界消息删除 ID`：软删除消息。

所有操作沿用现有永久 GM 身份校验，未注册或未授权玩家不能修改消息库。正文最大 180 字，解析时保留空格和标点。

## 5. 可靠性与降级

- 普通回复取得尾注时使用数据库行锁原子推进轮换状态。
- 数据库不可用或迁移尚未执行时，仅降级展示官方群提示，不阻断游戏回复。
- 已含官方群或世界消息尾注的内容不会再次追加，因此欢迎消息经过 HTTP 发送层时仍保持单一官方群尾注。
- GM 写操作仅在相关 SQL 全部成功后提交。

## 6. 部署步骤

1. 在业务数据库执行 `数据库源文件/p2_world_message.sql`。
2. 部署代码并重启 Webhook/WebSocket 服务。
3. 已验证的管理员发送 `GM世界消息` 检查首批攻略消息。
4. 使用两次普通玩家指令确认尾注依次出现官方群提示和世界消息。
