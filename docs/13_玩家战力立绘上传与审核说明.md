# 玩家战力立绘上传与审核说明

## 功能口径

玩家发送“更换战力立绘”后，可在 5 分钟内直接发送一张图片；也可在图片消息中同时填写“更换战力立绘”。系统从 QQ 消息事件的 `attachments` 读取 `content_type`、`url`、文件名和尺寸信息，不要求玩家复制外链。

QQ 开放平台官方 SDK 将 C2C 与群消息统一映射为入站消息，并保留 `attachments`；附件结构包含 `content_type`、`url`、`filename`，部分事件还提供宽、高和大小。实现参考：[腾讯 QQ 开放平台 Node.js SDK](https://github.com/tencent-connect/qqbot-nodejs)与[QQ 机器人事件订阅说明](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/event-emit.html)。

## 玩家流程

1. 发送“更换战力立绘”，然后发送一张图片；或直接发送带有该说明文字的图片。
2. 系统仅接收一张 JPG、PNG 或 WebP；下载上限 8MB，宽高至少 300 像素，解码后总像素不超过 3600 万。
3. 系统重新编码为统一 JPEG，写入版本目录外的随机文件名，不保留玩家提供的路径。
4. 新提交进入 `PENDING`。审核前继续使用原来已通过的立绘；没有已通过立绘时继续使用角色默认图。
5. 发送“立绘状态”可查看最近提交状态与驳回原因。

## GM 流程

- `GM立绘审核`：查看待审队列。
- `GM查看立绘 编号`：预览图片与提交信息。
- `GM通过立绘 编号`：令该图片成为玩家当前自定义立绘。
- `GM驳回立绘 编号-原因`：驳回并保存玩家可见的原因。

GM 预览和战力图片均标记为核心图片，不受“关闭图片模式”影响，否则无法完成内容审核。

## 数据与文件

- 迁移：`数据库源文件/p14_power_portrait.sql`
- 表：`power_portrait_submission`
- 共享文件目录：环境变量 `POWER_PORTRAIT_DIR`
- 生产建议值：`/opt/qq-rpg/shared/power_portraits`

若旧环境尚未设置该变量，程序会优先使用 `GM_STATE_FILE` 所在共享目录下的 `power_portraits` 子目录，避免自动发布后暂存到版本目录；仍建议尽快显式配置生产路径。

表内记录待审、通过、驳回和被替换状态，并保存图片摘要、尺寸、提交消息 ID、审核人、审核时间与驳回原因。玩家再次提交时只替换尚未审核的旧提交，不改变当前已生效立绘；GM 通过新图时，旧的已通过记录转为 `SUPERSEDED`。

## 上线顺序

1. 创建并授权共享目录给 `qqbot` 服务用户。
2. 在业务库执行 P14 幂等迁移。
3. 配置 `POWER_PORTRAIT_DIR`。
4. 发布代码并先用测试玩家提交图片。
5. 用已验证 GM 完成通过、驳回各一次，再检查“战力图片”的默认回退与生效切换。
