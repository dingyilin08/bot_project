# 《诸天灵契》灵兽子系统接入记录

## 1. 实装结论

《灵兽玩法全面重制设计文档》中的阶段 A—D 已合并完成。本次实现保留旧灵兽实例编号、资质、羁绊与角色绑定，并以 V2 表承载寻踪、鉴灵、六线养成、一主两辅灵阵及长期玩法。

已接入范围：

- 四只通用初契灵兽与六界18只核心灵兽；
- 三线索寻踪、10次地品保护、60次天品硬保底、重复灵兽三选一；
- 等级、七重境界、四维洗髓、性情、六节点共享血脉、无损技能书库、十级羁绊与四章传记；
- 每名角色独立的一主契、护契、辅契，世界共鸣、五行灵阵、三套预设和六角色协同；
- 普通副本、扫荡、轮海深渊、组队、世界 Boss、洞府派遣、宗门御兽学与护山灵兽、万灵秘境、周记、赛季、切磋；
- 单只及批量归真、每周免费次数、高价值保护、迁移首周免费调整；
- QQ Markdown 菜单、正文文本交互、角色页、战力页与四篇玩家指令攻略。

## 3. 数据迁移与资产守恒

执行顺序：备份数据库 → 执行 `p8_spirit_beast_v2.sql` → 发布代码 → 冒烟验证。

迁移规则：

1. 赤焰灵狐、玄甲龟、青木鹿、寒翎雀保留原实例 ID；
2. 旧单资质等额映射为灵力、体魄、神魂、迅捷，收益不降低；
3. 原羁绊经验、获得时间及角色绑定完整迁入；
4. 原出战灵兽进入对应角色的主契位；
5. 超出灵兽园容量的旧灵兽全部保留，只暂停继续鉴灵；
6. 旧灵兽获得“初代灵契”纪念标记；
7. 迁移角色首周开放免费归真，之后恢复每周前三次免费；
8. 基础兽材使用 `user_item` 普通背包作为唯一库存，可参与坊市交易；其他灵兽资源保存在绑定钱包。

核心表包括：模板、实例、四维资质、血脉、技能书库/槽位、角色灵阵/设置、图鉴、寻踪、保底、待确认选择、奖励账本、派遣、每日活动、周记、秘境、归真、宗门护山灵兽。

## 4. 事务与安全规则

- 鉴灵、洗髓确认、血脉激活、技能装配、归真与奖励领取在单一事务内校验并提交；
- 奖励账本以业务键阻止副本首通、重复选择、归真和赛季奖励重复发放；
- 洗髓只在确认令牌有效时覆盖，预览和取消不改变现有资质；
- 地品、天品、已命名、已锁定、羁绊5级以上灵兽必须单独二次确认；
- 批量归真自动排除高价值、上阵与派遣对象，确认时再次加锁校验；
- 灵阵位置、技能槽位及相同实例由主键/唯一键兜底并发冲突；
- 派遣奖励在开始时冻结，取消按真实完成比例结算，重复领取不会重复发奖。

## 5. 战斗与战力

V2主契战力由四维平均、等级、境界、血脉、羁绊和有效品质共同计算，只计入绑定角色，不写回角色永久基础属性。角色总战力仍为：

`基础 + 等级 + 装备 + 本源 + 技能 + 灵兽`

开战时冻结主契、护契、辅契、技能、血脉、共鸣和角色协同。主契在主人行动后自动协战；护契与辅契只按条件有限触发。常驻攻击、防御、速度不超过12%，单次治疗不超过8%，护盾与破阵不超过10%，强回复与强驱散每场最多一次。

Boss机制失败会损伤主契独立灵体，归零后灵兽本场退阵而角色继续战斗。轮海深渊开层后不允许实时换阵，每只怪物间恢复30%灵体并把状态写回运行记录。

## 6. 玩法接入规则

- 普通副本：手动前三场每日给羁绊；首次完整通关给兽踪、灵息和基础兽材；
- 扫荡：只给基础兽材和少量灵息，不给羁绊、兽踪与故事；
- 组队：每人展示自己的主契，护辅效果写入各自状态，同类团队效果取最高；
- 世界 Boss：伤害、辅助、净化均可获得灵兽贡献资源，每周轮换一个定位弱点并封顶5%；
- 洞府：灵兽园每日产灵息，Lv.4/7解锁护辅，Lv.10解锁一键照料和三套预设；
- 派遣：巡山、采药、探矿、寻迹支持4/8/12小时及批量领取；
- 宗门：御兽学只增加护山供养追赶材料，不增加个人永久攻击；
- 万灵秘境：每周两个世界，血脉/技能/羁绊三路线，首次失败不扣次数；
- 赛季：复用真实赛季经验，发放故事信物、改名牌和纪念外观，不出售限定战力。

首屏“灵兽菜单”保持八个核心入口：灵兽主页、我的灵兽、六界寻踪、配置灵阵、万灵秘境、洞府派遣、六界图鉴、灵兽周记。

详情页负责承接培养、血脉、技能、洗髓、传记和归真；所有需补编号的按钮保留尾随空格。危险操作一律展示返还明细及确认/取消按钮。

## 8. 验证清单

- 规则测试：22只目录、六界各3只、10/60保底、未拥有保护、等级/境界上限、共鸣互斥、返还递增；
- 交互测试：带空格的技能卸下、一键照料、批量派遣、批量归真令牌可被解析；
- 战斗测试：主契自动协战、状态可序列化恢复、旧 V1 灵契继续兼容；
- 集成测试：洞府收益、角色绑定战力、副本/深渊/组队/世界 Boss 原有流程全部回归；
- 迁移检查：旧 ID、资质、羁绊、绑定与初代标记均有明确 SQL；
- 发布前执行 `python -m py_compile ...` 与 `python -m unittest discover -s tests`，只有全部通过后提交推送。
