# 设计文档索引

这些文档面向策划、主程和 CodingAgent。实现时应按依赖顺序阅读，不要跳过 P0 的状态与结算基础。

## 阅读顺序

1. [现状架构与玩法审视](00_问道诸天QQ机器人_现状架构与玩法审视.md)：项目事实、现有玩法、问题、风险和总体路线。
2. [战斗会话持久化与 QQ 交互](02_功能建议_战斗会话持久化与QQ交互.md)：P0 基础，先把当前 1v1 战斗变成可恢复、可操作、可幂等的会话。
3. [多人回合制秘境与组队](01_功能建议_多人回合制秘境与组队.md)：依赖战斗会话，新增队伍、多人行动、Boss 协作和组队奖励。
4. [宗门与赛季地图争夺](03_功能建议_宗门与赛季地图争夺.md)：依赖多人战斗和奖励流水，作为 P2 长线玩法。
5. [Battle Session 实现说明](04_BattleSession_实现说明.md)：本次已落地的代码、迁移和旧副本切换边界。

## 实现约束

- 先迁移数据表，再接 Service，再接命令路由和 QQ 展示。
- 消息层不能直接改玩家数据；奖励必须经过带唯一业务键的流水服务。
- 纯文本命令必须始终可用，按钮是交互增强而不是唯一入口。
- 每完成一个阶段，都必须执行文档中的验收清单和并发/重复请求测试。
