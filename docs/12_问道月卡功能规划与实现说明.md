# 《问道诸天》月卡功能规划与实现说明

## 1. 功能定位

月卡是一项强调“持续登录、稳定积累”的轻付费权益。它不直接出售角色等级、装备、永久属性或限定战斗能力，主要向活跃玩家提供仙玉与少量灵石，兼顾游戏收入、日活留存和非付费玩家的公平体验。

首版采用“运营发放一次性月卡码，玩家在 QQ 内激活”的交付模式。这样无需等待支付平台接入即可上线，也能保留完整的生成、兑换、领取和资产流水。后续接入支付回调时，支付服务只需复用同一套激活事务，不需要改动玩家领取逻辑。

## 2. 首版权益

| 项目 | 规则 |
| --- | --- |
| 单卡有效期 | 30 个自然日，激活当天计为第 1 日 |
| 激活奖励 | 600 仙玉，兑换成功后立即到账 |
| 每日奖励 | 100 仙玉 + 200 灵石 |
| 完整周期总收益 | 3600 仙玉 + 6000 灵石 |
| 每日刷新 | 以数据库服务器 `CURDATE()` 为准 |
| 领取方式 | 玩家发送“领取月卡”主动领取 |
| 漏领规则 | 不补领、不累计到次日 |
| 续卡规则 | 有效期未结束时从原到期日次日顺延 |
| 累计上限 | 含当天最多保留 180 天有效期 |
| 战力影响 | 不提供永久属性、限定装备或付费专属技能 |
| 专属称号 | 有效期内自动展示「月华玩家」，到期自动隐藏 |
| 上线世界消息 | 满足防刷条件时展示“尊贵的月华玩家XXX已上线！” |

设计理由：

- 仙玉能自然承接现有角色祈愿与药园解锁，不创建新的付费货币。
- 灵石投放约等于每日一次便利补给，不替代副本、参悟、药园和坊市的主要产出。
- 主动领取给玩家一个稳定的每日回访理由；漏领不补可以控制负债式奖励和客服成本。
- 激活奖励让玩家兑换后立即感知价值，每日奖励承担长期留存作用。
- 180 天上限可以降低错误批量兑换、盗号囤积和超长期财务负债风险。

### 2.1 功能特权首发规划

以下五项首发功能特权均已接入炼丹、药园、参悟、副本和坊市。它们只改变时间、次数或交易成本，不直接修改攻击、防御、暴击等角色属性。

| 特权名称 | 已实现效果 | 结算与限制 |
| --- | --- | --- |
| 丹火增益 | 炼丹耗时减少 20% | 仅缩短等待，不增加丹药数量与品质；任务开始时生成快照 |
| 灵田滋养 | 药材成熟时间减少 20% | 不增加产量；已播种药田按开始时快照结算 |
| 悟道静室 | 参悟耗时减少 15% | 经验与灵石奖励不变；与其他减时效果乘法叠加 |
| 历练充盈 | 每日副本基础历练次数增加 5 次 | 不提高掉率；月卡到期后不再新增额度，已开始副本可完成 |
| 坊市优待 | 坊市成交手续费由 8% 降至 5% | 不改变系统底价、交易冷却与成交顺序 |

所有百分比减时统一采用乘法叠加，并设置总缩减不超过 50%的硬上限，防止与洞府、宗门、角色特性叠加后出现零等待。

### 2.2 后续候选特权池

候选特权不会默认一次性全部开放。每个版本应根据资源投放、付费转化和非付费玩家差距选择 2—3 项灰度验证。

| 特权名称 | 候选效果 | 平衡限制 |
| --- | --- | --- |
| 炼器折扣 | 装备强化灵石消耗降低 5% | 与宗门减免合计最多 15% |
| 灵兽亲和 | 灵兽派遣时间缩短 15% | 不增加派遣奖励 |
| 洞府聚灵 | 洞府每日基础收取提高 10% | 不放大冒险共鸣等随机倍率 |
| 扫荡优待 | 每日前 3 次扫荡不消耗扫荡券 | 仍消耗历练次数 |
| 体力充盈 | 使用体力药额外恢复 1 次历练 | 每日最多触发 5 瓶 |
| 丹炉扩容 | 同时炼丹队列增加 1 个 | 不免费解锁需要仙玉的丹炉 |
| 灵田托管 | 成熟药材自动保鲜 | 不自动采摘、不增加产量 |
| 悟道护持 | 参悟完成奖励可保留 48 小时 | 不提高奖励数值 |
| 强化护佑 | 每日首次强化失败返还 50%灵石 | 不返还其他材料，每日一次 |
| 坊市扩摊 | 同时上架数量增加 2 个 | 到期后保留超额订单，但不能继续新增 |
| 坊市延时 | 商品与收购单有效期延长 50% | 不改变价格与成交优先级 |
| 签到补录 | 每 30 日提供 2 次普通签到补录 | 不补月卡奖励，不跨月累计 |
| 日常捷径 | “今日修行”提供一键领取 | 只领取已完成奖励，不自动完成任务 |
| 到期提醒 | 剩余 3 日、1 日时发送提醒 | 每个自然日最多一条 |

### 2.3 月华称号与上线播报

- 称号固定为 **「月华玩家」**，不需要手动装备；月卡有效时自动显示，过期后自动隐藏。
- 首批展示位置为月卡主页与主菜单玩家名，后续可复用到战力仙鉴、排行榜和组队名片。
- 月卡玩家连续 6 小时没有游戏操作，之后再次发送有效游戏指令，视为重新上线。
- 同一玩家每个自然日最多触发一次上线世界消息，固定文案为：`尊贵的月华玩家XXX已上线！`
- 上线消息进入临时世界消息队列，优先于常驻攻略轮播展示；成功展示后立即消费，30 分钟未展示则过期。
- 玩家连续点击、QQ 重投、服务多实例并发均由每日唯一事件键防重；上线状态记录失败时降级为普通回复，不阻断游戏指令。

## 3. 玩家交互

### 3.1 指令

- `月卡`：查看权益说明、当前到期日、剩余天数、今日领取状态与最近 5 次领取记录。
- `月卡兑换 月卡码`：兑换一次性月卡码；也兼容按钮填入后再补充月卡码。
- `领取月卡`：领取当天奖励。

### 3.2 推荐交互路径

1. 玩家在活动菜单点击“问道月卡”。
2. 未激活玩家点击“填写月卡码”，输入运营交付的月卡码。
3. 系统在同一事务中完成月卡码核销、有效期顺延、600 仙玉发放和激活流水记录。
4. 玩家点击“领取今日奖励”，系统发放 100 仙玉与 200 灵石。
5. 已领取玩家再次操作时只收到“今日已经领取”的提示，不重复发奖。

### 3.3 QQ 展示原则

- 首页只展示权益、状态和三个主要动作，避免将月卡页做成长菜单。
- Markdown 正文保留蓝字命令，同时提供 QQ Keyboard，适配群聊填入与私聊直接执行。
- 日期显示为明确的到期日，并注明“含今日剩余”，避免自然日和 24 小时制理解差异。
- 月卡入口放入“活动菜单”，与签到、赛季等周期玩法集中展示。
- 生效中的主菜单玩家名显示为“「月华玩家」玩家名”，月卡主页同步展示称号状态。
- 临时上线播报沿用现有“🌏 世界消息”尾注样式，不额外主动轰炸所有群聊。

## 4. 运营与 GM 流程

### 4.1 生成月卡码

管理员验证身份后发送：

```text
GM生成月卡码 5
```

单批可生成 1—20 枚。每枚代码为 `MC-XXXX-XXXX-XXXX` 格式，只能成功兑换一次。系统记录生成管理员、批次、创建时间、兑换玩家和兑换时间。

建议运营流程：

1. 按实际订单数量小批量生成，避免长期保存大量未使用代码。
2. 在订单系统或客服工单中记录“订单号—批次号—月卡码—玩家”关系。
3. 只通过私聊向目标玩家发送代码，不在群内明文发放。
4. 对退款、拒付或异常订单，不直接修改玩家资产；由管理员依据激活与领取流水人工审计。

### 4.2 建议售卖策略

首发阶段建议只保留一种 30 日月卡，减少用户理解和客服成本。实际人民币定价应结合支付渠道费率、当前仙玉直充比例和合规要求确定，不在游戏代码内硬编码价格。

可以采用以下运营节奏：

- 首月上线：仅售 30 日标准月卡，观察激活率、日领取率和祈愿消耗变化。
- 稳定阶段：允许连续续卡，但继续保持 180 天上限。
- 节日活动：可追加全服活动奖励，不提高月卡本身的永久战力。
- 不建议首版推出“豪华月卡”“终身卡”或月卡限定角色，以免快速扩大数值差距。

## 5. 数据与事务设计

迁移文件：`数据库源文件/p13_monthly_card.sql`。

| 数据表 | 用途 | 关键幂等约束 |
| --- | --- | --- |
| `monthly_card_redeem_code` | 一次性月卡码与核销状态 | `redeem_code` 唯一 |
| `user_monthly_card` | 玩家当前有效期与累计领取状态 | `uid` 主键 |
| `user_monthly_card_activation_log` | 每次激活前后有效期和仙玉余额审计 | `code_id` 唯一 |
| `user_monthly_card_claim_log` | 每日奖励及发放前后余额审计 | `(uid, claim_date)` 唯一 |
| `user_monthly_card_presence` | 月卡玩家最后活跃与最近播报时间 | `uid` 主键 |
| `world_message_event_queue` | 限时上线播报等动态世界消息 | `event_key` 唯一 |

兑换时锁定月卡码、玩家资产和玩家月卡行；领取时锁定玩家资产和月卡行。资产变更、状态变更、兑换码核销和流水写入全部在一个数据库事务中提交，任一步失败都会整体回滚。

数据库唯一键是最终防重保障，即使 QQ 重试、玩家连续点击或服务并发处理，也不能让同一月卡码重复兑换，或让同一玩家在同一自然日重复领取。

## 6. 异常与边界规则

- 未注册玩家：沿用统一注册拦截，不进入月卡事务。
- 空月卡码或格式错误：展示填写示例，不查询资产。
- 不存在、已使用、停用或过期月卡码：不改变有效期和余额。
- 月卡已到期：不能领取；重新激活时从当天重新计算 30 日。
- 有效期内续卡：从原到期日顺延 30 日；超过 180 日上限则拒绝本次兑换，月卡码保持可用。
- 当天已经领取：不重复发奖，返回明确状态。
- 服务异常：事务回滚，月卡码、有效期、余额和流水保持一致。
- 服务器重启：所有状态都在 MySQL 中持久化，不依赖进程内定时器。
- 连续操作：5 分钟进程缓存减少重复在线检查，数据库仍保留跨进程与重启后的防刷状态。
- 上线播报：离线不足 6 小时或当天已经播报时只更新在线状态，不创建新世界消息。
- 月卡到期：称号、上线播报资格和功能特权同步失效，不删除历史领取与激活流水。

## 7. 支付平台接入预留

正式支付应由可信后端处理，不能让玩家发送“购买成功”之类的普通 QQ 指令直接获得权益。推荐流程：

1. 支付服务创建唯一订单，记录玩家 UID、商品、金额和渠道单号。
2. 支付平台异步回调到服务端，服务端验签并校验金额、商户号与订单状态。
3. 以渠道交易号作为幂等键，仅允许订单从“待支付”变为“已支付”一次。
4. 支付事务调用与月卡码兑换相同的有效期计算和激活记录逻辑。
5. 回调成功后通过 QQ 事件信箱通知玩家；玩家仍使用“领取月卡”领取每日奖励。
6. 退款或拒付进入独立审计流程，不应直接删除领取流水。

需要补充的支付表建议为 `monthly_card_order`，至少包含订单号、UID、商品快照、金额、渠道、渠道交易号、状态、创建时间、支付时间和退款状态。

## 8. 监控指标

上线后建议每日观察：

- 月卡码生成数、兑换数、未兑换库存和异常失败数。
- 激活玩家数、续卡率、平均剩余天数和接近 180 日上限人数。
- 月卡每日领取人数、领取率、连续 7 日领取率。
- 月卡仙玉投放量、总仙玉投放占比、祈愿消耗率和玩家仙玉存量。
- 月卡灵石投放量、灵石商城消耗、坊市成交价和通胀变化。
- 同日重复请求次数、无效月卡码尝试次数和跨账号兑换争议。
- 月华称号展示人数、上线播报入队数、实际展示数、过期数和每日防重命中数。
- 各功能特权带来的炼丹/种植/参悟完成频次、额外副本次数及坊市手续费变化。

若仙玉库存持续增长而消耗不足，应优先优化现有祈愿与便利消耗，不建议直接提高月卡奖励；若灵石价格体系明显通胀，可下调后续新批次的每日灵石或增加非战力型灵石回收项，但已售权益不应追溯削减。

## 9. 验收清单

- 玩家可通过“活动菜单 → 月卡”进入功能。
- GM 可生成 1—20 枚 30 日月卡码，非管理员无法生成。
- 月卡码兼容大小写和带连字符格式，且只能兑换一次。
- 首次激活、过期后重新激活和有效期内续卡的日期均正确。
- 兑换后 600 仙玉到账，并可在激活当天领取每日奖励。
- 同一玩家同一天只能获得一次 100 仙玉与 200 灵石。
- 有效期最多累计 180 天，超限失败时不核销月卡码。
- 领取、激活与资产流水可相互核对。
- 所有命令在 QQ Markdown 与 Keyboard 中均可正常操作。
- 生效月卡在月卡页和主菜单展示「月华玩家」，到期后不再展示。
- 月卡玩家离线满 6 小时后上线可生成指定文案，且同一自然日最多一次。
- 临时上线消息优先展示且只展示一次，过期消息不会进入世界消息尾注。
- 数据库迁移可重复执行，完整自动化测试通过。

## 10. 后续迭代优先级

1. **P1：支付订单与验签回调。** 用订单幂等键直接激活权益，月卡码保留给客服和活动渠道。
2. **P1：今日修行提示。** 在“今日修行”中仅对生效且未领取玩家展示月卡领取入口。
3. **P2：到期提醒。** 剩余 3 日和 1 日时通过事件信箱提醒，限制每日最多一条。
4. **P2：运营报表。** 按批次查看兑换率、领取率和资源投放。
5. **P2：功能特权灰度。** 先接入丹火增益与灵田滋养，再依据资源产出数据逐步开放其余候选特权。
6. **P3：称号展示扩展。** 将「月华玩家」复用到战力仙鉴、排行榜和组队名片，并与赛季称号明确展示优先级。
