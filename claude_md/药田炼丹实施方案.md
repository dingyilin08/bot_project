药园与炼丹系统 — 实现规范

  1. 系统概述

  药园系统允许玩家种植药材，炼丹系统将药材炼制为丹药以获得永久属性加成或辅助突破。两个系统构成一条完整的资源产出链：

  灵石购买种子 → 药田种植 → 2小时成熟 → 采摘药材 → 药材+灵石投入丹炉
  → 1小时炼制 → 收丹(90%成功/10%炸炉) → 服丹获得永久属性

  准入条件： 已注册且已选择角色（使用 @reg_xz_func 装饰器）

  5. 核心流程

  5.1 种植 → 采摘

  购买种子(灵石) → 种子进入 user_seed_bag
      ↓
  播种(种子名-田号) → 扣减 user_seed_bag, 写入 yt_N JSON {is_zz:1, zz_id, time:now}
      ↓
  等待 7200 秒（2小时）  // 或施肥跳过
      ↓
  采摘(田号) → 判断 now - time >= 7200
      ├─ 未成熟 → 返回剩余时间 "还需 XX 分 XX 秒"
      └─ 已成熟 → random(min, max) 根据 tier 产出药材
                  写入 user_item(uid, cl_id, num)
                  重置 yt_N = {is_zz:0, zz_id:0, time:0}

  产出数量区间（按 tier）：
  ┌──────┬──────┬──────┐
  │ tier │ 最少 │ 最多 │
  ├──────┼──────┼──────┤
  │ 1    │ 8    │ 12   │
  ├──────┼──────┼──────┤
  │ 2    │ 6    │ 10   │
  ├──────┼──────┼──────┤
  │ 3    │ 4    │ 8    │
  ├──────┼──────┼──────┤
  │ 4    │ 2    │ 5    │
  └──────┴──────┴──────┘
  5.2 炼丹 → 服丹

  炼丹(丹药名-炉号)
      → 查 data_recipe 获取 ingredients, need_num, cost
      → 扣灵石 cost
      → 逐一检查 user_item 中各原料 >= need_num
      → 逐一扣减原料
      → 写入 dl_N = {is_lz:1, df_id:recipe_id, time:now}
      ↓
  等待 3600 秒（1小时）  // 或加速卡跳过
      ↓
  收丹(炉号) → 判断 now - time >= 3600
      ├─ 未完成 → 返回剩余时间
      └─ 已完成 → roll = random(1,100)
          ├─ roll > 10 (90%) → 成功，add user_item(uid, pill_id, 1)
          └─ roll <= 10 (10%) → 炸炉，无产出
          → 重置 dl_N = {is_lz:0, df_id:0, time:0}

  5.3 服丹效果应用

  服丹(丹药名-数量)
      → 查 data_pill 获取 effect_type, effect_value, is_percent, max_use
      → 查 user_role.pill_usage 获取已用次数
      → 判断 已用 + 数量 <= max_use
      → 循环 N 次:
          ├─ effect_type = "gongji" → UPDATE user_role SET gongji = gongji + effect_value
          ├─ effect_type = "fangyu" → UPDATE user_role SET fangyu = fangyu + effect_value
          ├─ effect_type = "qixue"  → UPDATE user_role SET qixue = qixue + effect_value
          ├─ effect_type = "exp"    → 按百分比加经验
          ├─ effect_type = "sell"   → 直接加灵石
          └─ effect_type = "baoji/shanbi/mingzhong/pofang"
                → UPDATE user_role SET {attr} = {attr} + effect_value (百分比小数)
      → 更新 pill_usage 计数
      → 扣减 user_item

  6. 加速机制

  施肥（药田加速）

  - 消耗道具：植物肥料（需在 data_item / user_item 中新增此道具，建议 item_id 预留）
  - 效果：将 yt_N.time 设为 now - 7200，使时间差判定为已成熟
  - 来源：副本掉落 / 商店购买 / 活动产出

  加速炼丹（丹炉加速）

  - 消耗道具：炼丹加速卡
  - 效果：将 dl_N.time 设为 now - 3600
  - 来源：同上

  这样避免在注册时就创建大量空行。

  13. 注意事项

  1. JSON 字段读写 — MySQL 5.7 支持 JSON 类型但函数有限，建议在 Python 侧用 json.loads / json.dumps 处理，数据库仅做存
  2. 并发安全 — 采摘和收丹操作使用类似参悟系统的乐观锁模式：先 UPDATE 改状态，检查 rowcount == 1 再发放奖励
  3. 参数解析 — 后缀参数统一用 - 分隔（如 购买种子 仙露种子-5），在函数内 split('-') 解析
  4. 分页 — 种子商店和丹方列表参考现有模块的分页方式，每页 8 条
